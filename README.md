# Xiaomi MI 8 Pro (equuleus) — TWRP 16

Independent device branch `twrp-16.0-equuleus`, based on latest Dipper core baseline `aee2411485463c7f3389a40caf95f7404ef2b240`.
Hardware comes from this device's reference tree and available device reports; it is not generated by renaming the Dipper tree.

## Build status

Source preparation only; no compilation or new hardware verification has been performed.
Upload this device's kernel and DTBO to `prebuilt/` through the importer before building.
Perseus retains the previously bootable V1.70 pair. Equuleus awaits its own pair.
Each branch has a manual-only single-device workflow. A push never starts compilation.

## Included

Ext4/F2FS userdata mounting in storage mode, Ext4/EROFS system mounts and raw image backups,
Boot/Recovery/DTBO/firmware/EFS backup entries, guarded raw partitions in Advanced Wipe,
Cache settings persistence, real battery sysfs reading, checked fsck exit status,
Android installation detection, log collection and a 4-second ZC_J1an9 startup screen.
Perseus uses physical cust as `/system_ext`, matching the working recovery; Equuleus keeps `/cust`.
No assumed Super partition, MultiROM, duplicate legacy services or future-dated patch overrides.

## Local preparation

```sh
python3 tools/configure-storage.py --mode storage
python3 tools/preflight.py --source-only
python3 tools/import-prebuilts.py --kernel /path/Image.gz-dtb --dtbo /path/dtbo.img
python3 tools/preflight.py
bash tools/sync-source.sh /path/android-source
bash tools/build.sh /path/android-source
python3 tools/verify-image.py /path/android-source/out/target/product/equuleus/recovery.img
```

Storage mode does not decrypt encrypted data. Diagnostic mode omits userdata.
Modern FBE needs the installed ROM fstab, key services and compatible device blobs; it is not claimed here.
The earlier Perseus reboot-to-recovery issue is unresolved; partition configuration alone does not prove its cause or fix.
See `device-profile.json`, `prebuilt/README.md` and `SOURCES.md`.
